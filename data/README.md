## Feature 2 — `celestrak/` (REAL, in use)

Public US Space Force catalogue served by [CelesTrak](https://celestrak.org), no credentials
required. Downloaded 2026-08; copied here so this project is self-contained.

| File | Rows | What it is |
|---|---|---|
| `satcat.csv` | 70,288 | master catalogue: 35,834 debris, 27,414 payloads, 6,881 rocket bodies |
| `gp-cosmos-1408-debris.csv` | 3 | GP element sets, Cosmos 1408 cloud |
| `gp-cosmos-2251-debris.csv` | 591 | GP element sets, Cosmos 2251 cloud |
| `gp-fengyun-1c-debris.csv` | 1,937 | GP element sets, Fengyun-1C cloud |
| `gp-iridium-33-debris.csv` | 111 | GP element sets, Iridium 33 cloud |
| `gp-active.csv` | 16,345 | active payloads |
| `spatial_density.csv` | 14 | *generated* — measured debris density per 100 km shell |

**Trap worth knowing:** the `gp-*.csv` files contain only objects **still in orbit**. Building
a break-up cloud from them keeps survivors only, which biases every lifetime towards infinity
— Cosmos 1408 reads as 3 fragments and 0 % decayed instead of 1,805 and 99.8 %. Clouds are
therefore built from `satcat.csv` by international designator prefix, which is what
`cosmos.debris.load_breakup_cloud` does.

## Feature 3 — `derived/measured_lifetimes.csv` (REAL, in use)

Generated by `cosmos.debris.export_derived()`. For debris from a break-up whose date and
altitude are known, `DECAY_DATE` minus the break-up date is a **directly measured orbital
lifetime** — real ground truth, not a simulation.

- 7,711 fragments from 4 dated break-ups
- 4,652 have re-entered (`observed = True`)
- 3,059 are still in orbit (`observed = False`) — **right-censored**: their lifetime is only
  known to be *at least* their current age. `cosmos.debris.calibrate_area_to_mass` handles
  this properly and reports how far the fit moves if you ignore it.

## Feature 2 — `vision/yolo_dataset/` (simulated, in use)

Generated by `cosmos.debris.export_yolo_dataset()`. Standard YOLO layout so the reference
pipeline (Ultralytics) can train on it unchanged:

```
train/images/*.png   train/labels/*.txt   val/images/  val/labels/   data.yaml
```

Labels are `class cx cy w h`, normalised to `[0, 1]`, images 640×640. Four classes:
`satellite`, `rocket_body`, `fragment`, `panel`. Detector inputs are the **registered
difference** images, because that is the input on which a fragment is separable from a star.

## Regenerating

```python
import cosmos
cosmos.debris.export_derived()                                    # feature 2 + 3 derived CSVs
cosmos.debris.export_yolo_dataset(cosmos.debris.generate_dataset(48))   # vision dataset
```

To refresh the raw catalogue from CelesTrak (about 10 MB, no login):

```bash
bash ../scripts/fetch_real_data.sh && cp ../data/celestrak/*.csv data/feature2_debris/celestrak/
```

# COSMOS-AI datasets (added 2026-10-24)

Every dataset folder below has a `MANIFEST.json` with source URLs, DOI or record IDs, licence,
retrieval time, and per-file size and checksums (MD5 checked against the publisher where one
is published). `data/DATASET_REPORT.json` holds the validation results recomputed from the
files (counts, labels, missing values, corrupt files, cross-split duplicates).

```
python -m cosmos.ai.data.download status                     # what is here
python -m cosmos.ai.data.download opssat_ad esa_adb spotgeo celestrak
python -m cosmos.ai.data.preprocess_telemetry 1 2           # ESA-ADB official grids
python -m cosmos.ai.vision.spotgeo preprocess               # SpotGEO front end
python -m cosmos.ai.data.validate                           # -> DATASET_REPORT.json
```
