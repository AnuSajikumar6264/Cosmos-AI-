The following data were **not** available:

- **Space-Track and ESA DISCOS.** Their element-set histories and re-entry records require an account or token, and no access control was bypassed.

Two properties of these counts shape the interpretation of the results.

1. **The calibration windows differ sharply.** The Mission 1 window holds {{data.esa.m1.events_target.cal.events}} events. The Mission 2 window holds {{data.esa.m2.events_target.cal.events}}, all of them rare nominal events.
2. **The Mission 2 test half is dominated by rare nominal events.** It holds {{data.esa.m2.events_target.test.Rare_Event}} rare events against {{data.esa.m2.events_target.test.Anomaly}} anomalies. Anomaly-only results on Mission 2 therefore rest on {{data.esa.m2.events_target.test.Anomaly}} events.

Of the {{data.esa.m1.classes.test}} event classes in the Mission 1 test half, {{data.esa.m1.classes.test_unseen}} never occur in the training half. On Mission 2, {{data.esa.m2.classes.test_unseen}} of {{data.esa.m2.classes.test}} test classes are unseen.

- **OPSSAT-AD.** It contains {{data.opssat.fragments:int}} fragments from {{data.opssat.channels}} channels, with an anomaly fraction of {{data.opssat.anomaly_fraction:.3f}}. - **SpotGEO.**
  - The training set holds {{data.spotgeo.train.sequences:int}} sequences, {{data.spotgeo.train.frames_on_disk:int}} frames and {{data.spotgeo.train.objects:int}} labelled object positions.

  - The median box size is about {{data.synvis.train.box_median_px:.1f}} px.
- **Re-entry landmark.**
  - The population at risk holds {{data.landmark.population_at_risk:int}} objects with {{data.landmark.events}} re-entries during {{data.landmark.follow_up_days}} days.
  - Training has {{lm.split.train.n:int}} objects ({{lm.split.train.events}} events), validation {{lm.split.val.n:int}} ({{lm.split.val.events}}) and test {{lm.split.test.n:int}} ({{lm.split.test.events}}).

## Hardware and software

All experiments ran on one server. The recorded environment is:

- **CPU:** {{env.cpu_count}} logical CPUs.
- **Accelerators:** Intel Arc Pro B60 GPUs. The run records give the device as "{{env.device_name}}", reached through PyTorch's XPU back end.
- **Software:** Python {{env.python}}, PyTorch {{env.torch}}, NumPy {{env.numpy}} and pandas {{env.pandas}} on {{env.platform}}.

The main computational costs were as follows:

- **TCN event scorer.** One Mission 1 run took {{evm.m1.tcn.train_seconds_total.mean:.0f}} s on average (five fold models and a final model; {{evm.m1.tcn.train_seconds_total.n}} runs).
- **XGBoost event scorer.** One run took {{evm.m1.gbt.train_seconds_total.mean:.0f}} s on {{cfg.gbt.nthread}} CPU threads, excluding prediction.
- **Out-of-fold AR(8) scores.** These took {{oof.m1.seconds:.0f}} s for Mission 1.

## Evaluation protocols

[@tbl:protocols] summarises the protocols. Three rules are common to all studies:

- every test set was scored once for each frozen configuration;
- selection used only training or validation data;
- seeds are reported as distributions.

| Study | Split | Selection | Test | Seeds |
|---|---|---|---|---|
| ESA-ADB exploratory (H1–H3) | official 50/50 | early stopping on *es*; calibrator by cross-fitting on *cal* | official test half | 3 (deep), 1 (deterministic) |
| ESA-ADB pre-registered (H4–H6) | official 50/50; training half in 5 out-of-fold blocks | cross-fitting on the two training-half halves | official test half, gated by the freeze | 5 (A2, A3), 3 (ablations) |
| OPSSAT-AD | official, and time-blocked (75 % / 25 % by start time) | stratified 20 % of training | held-out test | 5 |

## Statistical procedures

The procedures differ by study:

- **ESA-ADB:** paired block bootstraps with fixed 30-day blocks ({{data.esa.m1.test.blocks30}} on Mission 1, {{data.esa.m2.test.blocks30}} on Mission 2) and hierarchical seed resampling ([@sec:theory-stats]), with Holm correction for the pre-registered family. The exploratory comparisons use {{explo.boot.h2.m2.ar8_conformal_bh_vs_threshold.n_boot:int}} replicates of the same block bootstrap on seed-0 arms. The pre-registered comparisons use {{conf.m1.h6.n_boot:int}}.
- **OPSSAT-AD:** paired i.i.d. bootstraps on seed-averaged test scores (2,000 replicates).
- **Landmark:** bootstraps that resample test launch groups ({{lm.cmp.hazard_mlp_vs_xgboost.h68.n_boot:int}} replicates).

Intervals are two-sided 95 % percentile intervals.
